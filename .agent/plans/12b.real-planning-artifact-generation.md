# Plan 12b: Real Per-Domain Planning Artifacts

**Complexity: Complex.** Completes Module 12 (R38-R40) by adding a deterministic, domain-derived planning-artifact layer and finishing the supplied hub-and-spoke interaction. This is deliberately split into backend artifact derivation, API, frontend rendering, and verification within one confirmed Complex plan.

## Requirement

Complete R38-R40 without using ARCHITEQ's own repository documents as end-user content and without placeholder text. Every displayed claim must derive from the active domain's frozen Workflow Tree, Component Tree, Data Architecture, or generated renderer output.

## Scope decisions

1. The supplied mockup is authoritative for this surface: one central hub with an icon, title, filename, and short description; six fixed satellite positions (three per side); dashed curves measured from real card positions; diagram default; and a one-interaction Full text view.
2. Existing ARCHITEQ theme tokens remain the only color system. Code/path text uses a named monospace stack headed by JetBrains Mono, with fallbacks.
3. Six deterministic generators produce PRD, TDD, App Flow, Design Brief, Backend Schema, and Engineering Plan equivalents from real per-domain data. An artifact whose required domain source does not exist still uses R40's explicit unavailable state naming that source; this is a valid per-domain state, not fabricated content.
4. Component Tree absence is explicit for the conditional App Flow and Design Brief artifacts. Data Architecture absence is explicit for Backend Schema. No generator calls an LLM or imports ARCHITEQ's own documentation as content.

## Build

1. Add a planning-artifact model/service that returns document metadata, structured hub spokes, and full Markdown derived from the frozen domain artifacts.
2. Add an authenticated read endpoint for one domain's artifact collection and cover normal plus unavailable-source cases.
3. Replace Module 12's hardcoded status map with API-backed artifact data. Render all real artifacts with the full mockup interaction: fixed six-position diagram, icons, equal spoke treatment, measured dashed connectors, a Full text toggle, and accessible unavailable states.
4. Preserve the existing Python folder browser and make Engineering Plan spokes navigate into its real layer/file content.
5. Update the design, PRD, progress, and open-question records to reflect the resolved source mappings and actual completion state.

## Validation

1. Backend tests prove each artifact is generated only from a supplied domain fixture, never ARCHITEQ self-documentation; absent Component/Data sources produce named unavailable states.
2. Frontend harness verifies six positioned spokes, diagram-first behavior, full-text toggle, measured dashed connector paths, source-specific unavailable states, and Engineering Plan navigation.
3. Run the relevant pytest suite and the project UI detector after UI edits.

## Commit

One commit after all validation passes: `Complete per-domain planning artifacts and Module 12.`
