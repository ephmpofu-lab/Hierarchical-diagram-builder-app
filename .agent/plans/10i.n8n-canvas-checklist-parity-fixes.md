# Plan 10i: n8n Canvas Checklist-Parity Fixes

**Complexity: Medium.** No new capability, no new schema -- a verification-driven pass over
already-committed Module 10/13 rendering code (`renderN8nDiagram`, the Python folder browser,
the mode/layer toggles) against `reference/architeq-ux-mockup.html` and a real rendered
screenshot, fixing every confirmed real gap between the two. Proceeds through Build/Test/
Commit per the Autonomy Default.

## Requirement

Prompted by a user-supplied checklist (derived from the mockup) that two prior rounds of
code-reading ("the function exists," "the git commit exists") had already claimed satisfied
without ever rendering the actual page. A real screenshot of the served app proved several of
those claims wrong. This plan closes every real gap the screenshot found, per new rule DP14
(`rules/principles/dev-process.md`): a UI-facing change is tested against a real rendered
screenshot, not its own source code.

## Method

Installed Playwright + headless Chromium in this environment (previously unavailable). Logged
into the real served app with a real Supabase session (test credentials supplied by the user,
used in-memory only, never written to a file or committed). Screenshotted the `rag` domain's
real n8n canvas and Python browser views, and the mockup's own equivalent states, side by
side. Iterated privately: fix, re-screenshot, repeat, until every checklist item genuinely
passed by pixel/DOM evidence -- never by re-reading the code that produced the prior, wrong
"verified" claim.

## What was actually wrong (confirmed by screenshot, not by code-reading)

1. Stage-zone labels showed the raw Layer name (`"Ingestion"`) with no `"STAGE — "` prefix.
2. No per-node short ID label existed at all (not "wrong format," genuinely absent).
3. Per-node icons were entirely absent from `renderN8nDiagram`.
4. "Needs configuration" was a bare, unlabeled circle badge -- no text, no border change on
   the node box, contradicting the "warnings don't replace the type line" intent (there was
   no text to replace it with in the first place).
5. Connection classification data (`classify_connections`, real since 10a-ii) was computed
   and attached to each path's `data-classification` attribute but consumed by zero CSS
   rules -- every connection rendered identically regardless of real classification.
6. No connection-data labels (the real `produces` name a step emits) rendered anywhere.
7. No colored per-Layer legend existed.
8. No "Auto-arrange" or "Export" control existed; a "Download workflow.json" button sat at
   the bottom of the section instead.
9. Data Anchors were correctly coded but gated behind a lazy fetch that only ever triggered
   on a manual "Data" tab click -- never visible on the canvas's own default (Workflow-active)
   first paint.
10. The Python|n8n and Workflow|Data toggles were two independent bordered buttons, not a
    single segmented pill.
11. `groupPythonRenderByFile` computed a real `architeq_{domain}/` package name (already used
    in the breadcrumb) but never rendered it as a folder row -- Layer folders appeared as
    flat top-level siblings of `docs/`. Folder order also followed `pythonRender`'s own
    topological (dependency) order rather than the tree's declared `root_ids` pipeline order.
12. `static/js/decompose.js` contained two literal NUL bytes (both inside the same
    `classificationByPair` key-construction template literal, one on the write side and one
    on the read side) -- harmless by coincidence (both sides broke identically so lookups
    still matched), but the reason `grep` kept reporting the file as binary all session.

Two items were checked and found to be intentional, not bugs, and were **not** changed:
- The Refine bar sits under the topbar, not floating bottom-right (10e's own build note:
  deliberate, because the real page is long and scrollable, unlike the mockup's fixed
  single-viewport canvas -- a bottom-right float would require scrolling past a 32-step tree
  to find it).
- No line-by-line reveal animation plays when opening an already-frozen domain's function
  code. 10d's progressive-build animation is real, but scoped to the *drafting* flow (a new
  domain being generated for the first time), not to browsing an already-approved domain's
  code -- applying it here would be the wrong moment in the product flow, not a missing
  feature.

## Build

- `static/js/decompose.js`: `n8nTypeIcon`/`N8N_TYPE_ICONS` (real n8n type -> glyph, covering
  every type in `rules/n8n_node_schemas.json` plus the Code fallback), `n8nDisplayId` (real
  domain name + sequential index over the render's own R10 topological order -- deliberately
  *not* the spec doc's own abstract `"WF01"` placeholder, per R44/OQ7's actual resolution),
  needs-config text line + `needs-config` rect modifier class, connection-data labels sourced
  from `state.tree`'s real `produces` field, `renderN8nStageLegend`, Auto-arrange (a real
  `renderBoard()` call -- honest given this canvas's layout is already fully deterministic,
  so "arranging" it again means resetting pan/zoom to the same computed fit) and Export
  (reuses the existing real `downloadWorkflowJson`) buttons, `ensureDataArchitectureLoaded`
  extracted and called eagerly from `selectMode("n8n")`, the `architeq_{domain}/` folder row
  in `renderPyLevel1`, `root_ids`-order sort in `groupPythonRenderByFile`. Fixed the two NUL
  bytes (replaced with the literal space the template string always intended).
- `static/css/style.css`: `.decompose-n8n-node-rect.needs-config`, `-node-id-text`,
  `-needs-config-text`, `-connection-label`, `[data-classification="local_branch"]`,
  `.decompose-n8n-topbar/-actions/-legend*`, segmented-pill styling shared by
  `.decompose-mode-toggle`/`.decompose-layer-toggle`, emoji-font fallback on
  `.decompose-n8n-node-text` (a headless/minimal font environment renders some icon
  codepoints as tofu without an explicit fallback in the chain -- confirmed via a real
  rendered screenshot before and after).

## Test

Real Playwright screenshots (not described -- actually rendered), before and after each
batch of fixes, of: the mockup's own n8n view (`reference/architeq-ux-mockup.html`, its own
"I want to develop a RAG" -> n8n toggle path) and the real served app's n8n + Python views
for the real `rag` domain (real login, real Supabase session). Confirmed via pixels: stage
labels, node IDs, icons (including the emoji-fallback fix, itself verified via a dedicated
glyph-rendering test page before touching the real app), needs-config border+text, dashed/
amber `local_branch` connections, connection-data labels, the legend, Auto-arrange/Export,
the pill toggles, and the Python view's `architeq_rag/` wrapper folder in correct pipeline
order. Data Anchor eager-fetch confirmed via network behavior and the correct empty-state
message (`rag` has no drafted Data Architecture, so no anchor text exists to render --
correctly absent, not a bug). Workflow/Data toggle state confirmed via direct DOM query
(`className` on both buttons) after an earlier screenshot read looked ambiguous by eye --
never trusted a pixel judgment call when a DOM query could settle it. Full pytest suite green
throughout (444 passed, same pre-existing `DATABASE_URL`-only failures as baseline, no
regressions -- this plan touched no backend Python).
