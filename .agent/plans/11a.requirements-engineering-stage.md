# Plan 11a: Requirements Engineering Stage (Stage -3)

**Complexity: Simple.** Single new AI-calling function, single new model, no schema-breaking
changes to any existing file. Part of Plan 11 (Dual Tree Architecture); first sub-plan in
the sequence.

## Requirement

R24 (`ARCHITEQ-PRD.md`): "Given the project's PRD, the system extracts a requirements list
relevant to the resolved domain, each item traceable to a specific PRD requirement ID."

## What this sub-plan does NOT do

Does not build Stage -2/-1/0, does not add an API endpoint (the endpoint arrives with the
orchestrating `propose_component_tree` in sub-plan 11d, once there's a full pipeline to
wrap — mirrors how the Workflow Tree's `draft`/`approve` endpoints wrap all of Stages 0-4,
not one stage each). Does not persist anything — this stage's output threads in-memory into
the next stage, same posture as the Workflow Tree's Stages 1-3 today.

## Build

1. **`backend/models.py`** — new model:
   ```python
   class ExtractedRequirement(BaseModel):
       text: str
       prd_requirement_id: str
       domain: str
   ```
2. **New package `backend/component/`** (parallel to the existing `backend/decompose/`,
   name deliberately distinct — this is the Component Tree track, not the Workflow Tree
   track): `backend/component/__init__.py`, `backend/component/engine.py`:
   ```python
   def extract_requirements(
       domain: str, prd_text: str, reasoning_context: str
   ) -> List[ExtractedRequirement]:
   ```
   One AI call via the existing `intelligence.stages._ask_json`/`_build` convention (same
   pattern `backend/decompose/engine.py::propose_checklist` already uses). Prompt: given
   the PRD text and the target domain, extract functional and non-functional requirements
   from the PRD's own Requirements section relevant to this domain, preserving each
   requirement's own id (R1, R2, ...) as `prd_requirement_id` — never inventing a new id.
   Any returned item missing a non-empty `prd_requirement_id` is dropped (defensive filter,
   not yet a full Validator pass — CD1's `traced_requirements[]` check happens once
   Capabilities exist, sub-plan 11b).

## Test (`tests/test_engineering_decomposition.py`, new test functions)

1. Mocked `_ask_json` returns 3 well-formed items (each with `text`/`prd_requirement_id`) —
   confirm `extract_requirements` returns exactly 3 `ExtractedRequirement` objects with
   `domain` set correctly.
2. Mocked `_ask_json` returns one item missing `prd_requirement_id` (empty string) among two
   well-formed ones — confirm the malformed item is dropped, the other two are returned.
3. Confirm the prompt text passed to `_ask_json` includes the literal PRD text and domain
   name passed in (regression guard against a prompt that silently drops the PRD content).
