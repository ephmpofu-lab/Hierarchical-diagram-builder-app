# Plan 10j: n8n Canvas Exact-Value Parity

**Complexity: Medium.** Follow-on to 10i. 10i fixed *which behaviors exist* (icons, IDs,
needs-config styling, legend, connection labels); this plan fixes the *exact numbers* behind
them, per an explicit instruction not to rely on the written spec's category descriptions --
read `reference/architeq-ux-mockup.html`'s own `:root` custom properties and JS layout
constants directly, and use those values, not an approximation of them.

## Requirement

Every color, spacing value, corner radius, gap, opacity, and animation timing on the n8n
canvas should match the mockup's own source values, read directly, not transcribed from a
description. Also: verify the stage-zone layout math (10a-i, unchanged in numeric value since
its own original build) actually holds for a real domain with more Layers than the mockup
ever defines colors or tests for (the mockup only ever names 3: Ingestion, Preprocessing,
Embedding; `rag` has 8).

## What direct source-reading found

Reading `reference/architeq-ux-mockup.html`'s `computeDefaultPositions()`/`drawN8nFlow()`
directly surfaced something no written description had: the mockup's exact layout numbers
(`gapX=110`, `gapY=150`, `tileSize=58`) are only consistent with a **58x58 square icon
tile** -- not the 180x58 wide rectangle 10i's own fix kept. The numbers and the tile shape
are coupled; matching one without the other doesn't produce the mockup's actual geometry.
This plan therefore rebuilds the node tile shape too, not only the numbers around it.

## Build

- `backend/render/node_mapper.py`: every stage-zone layout constant replaced with the
  mockup's own exact value (`_HORIZONTAL_SPACING`=168 i.e. tileSize+gapX,
  `_ROW_HEIGHT`=150 i.e. gapY, `_ZONE_HEADER_HEIGHT`=34 i.e. headerH, `_MAX_NODES_PER_ROW`=9,
  new `_STAGE_PAD_TOP`/`_STAGE_PAD_BOTTOM`=20/20 replacing the old single `_ZONE_PADDING`,
  new `_INTER_STAGE_GAP`=70 -- previously absent entirely, zones stacked with zero gap
  between them). `compute_stage_zones` restructured to apply top padding before content and
  the inter-stage gap between zones, matching the mockup's own `computeDefaultPositions`.
- `static/js/decompose.js`: node tile rebuilt as a 58x58 square (`rx=12`, matching the
  mockup's own tile rect) with a per-node layer-color dot (top-left inset, mockup's own
  `layerDot`, reusing the legend's own categorical palette so a node's dot always matches
  its stage's legend entry), a centered 22px icon (no longer prefixed onto the name line),
  and one stacked `<text>`/`<tspan>` label block below the tile (name, type, and -- only
  when unconfigured -- a warn-colored "needs setup" third line), matching the mockup's own
  `n8nDisplayLines`/`makeTile`. `N8N_CORNER_RADIUS` 12->14 (mockup's own `cornerR`).
  `N8N_LANE_OFFSET` recomputed for the new tile height (47, derived from the mockup's own
  branch-lane formula). Icon map (`N8N_TYPE_ICONS`) replaced with the mockup's own exact
  `nodeIcon` glyphs where a mockup entry exists (merge/postgres have none -- the mockup's
  own RAG demo never uses either -- so those two keep their own prior choice, documented as
  such); fallback glyph changed to the mockup's own `⬛`. Stage-zone rect/label now colored
  per-Layer inline (same categorical palette + index as the legend and node dots), mirroring
  the mockup's own `layerColor`-driven fill/stroke/label, rather than one flat neutral tone.
- `static/css/style.css`: stage-zone `fill-opacity:0.05`/`stroke-opacity:0.22`/`rx:12`
  (mockup's own exact values), zone label `font-weight:600`, connection-label `opacity:0.55`,
  needs-config border `stroke-width` 1.5->1.4, new `.decompose-n8n-node-icon` (22px, emoji
  font fallback) and `.decompose-n8n-node-label`/`-label-warn` rules replacing the old
  `-node-text`/`-node-type-text`/`-needs-config-text` (removed, no longer referenced).
  Node tile fill/stroke and port fill/stroke **deliberately kept on existing ARCHITEQ
  tokens** (`var(--surface)`/`var(--border)`/`var(--accent)`), not the mockup's own literal
  hex/`rgba()` values -- copying those would reintroduce a second color system, which 10h and
  12b both already explicitly ruled out. Only the categorical, non-semantic legend/zone/dot
  palette (an already-established exception, not a semantic token) takes exact mockup hex.
- `tests/test_engineering_decomposition.py`: `_multi_layer_tree_with_row_wrap`'s row-wrap
  assertions updated for the new 9-per-row cap (was hardcoded to a 10-per-row split).

## Real mistake caught during this plan's own verification

After editing `node_mapper.py`, an early re-screenshot showed the OLD geometry numbers
unchanged. The server process had been started earlier in the session without `--reload`;
`pkill -f "uvicorn app:app"` silently failed to match the actual Windows process (PID 1564
kept running), so a second `uvicorn` instance failed to bind port 8000 and exited immediately
-- and the next `curl` check hit the still-running *old* process, reporting a healthy 200 and
masking the failed restart. Only caught because the re-verification checked the real
`zone.height`/`zone.y` numbers via `getBBox()`, not just "does it look right" -- the numbers
matched the *old* formula (34->60, 20/20->0, 70->0) exactly. Fixed with `taskkill /F /PID`
(the actual PID from `netstat`), confirmed a single listener before re-testing.

## Test

Real screenshots + direct DOM/computed-style queries (not visual judgment alone -- this
session's own prior visual misreads, on this same canvas, are exactly why): tile
`width`/`height`/`rx` read via `getAttribute`, label tspan `fill` read via
`getComputedStyle` (confirmed `rgb(154,154,154)` = `#9a9a9a` = `--text-muted` for ordinary
lines, `rgb(245,158,11)` = `--warning` for the needs-setup line), zone label `fill`/
`font-weight` (confirmed `rgb(124,140,255)` = the mockup's own exact `#7C8CFF`, weight 600),
icon `font-size` (22px). The 8-Layer scaling question resolved with a direct measurement,
not a screenshot glance: `getBBox()` on all 8 real `rag` stage-zone rects, asserting
`zone[i].y + zone[i].height <= zone[i+1].y` for every adjacent pair -- zero overlaps, a real
70px gap between each (334 - (40+224) = 70, matching `_INTER_STAGE_GAP` exactly). Full
pytest suite green throughout (444 passed, same pre-existing unrelated failures).
