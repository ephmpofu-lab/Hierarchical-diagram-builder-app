# Plan 13c: SQL DDL Generator

**Complexity: Simple.** Deterministic, no AI call — a pure function of the canonical
`DataEntity`/`DataAttribute` model, mirroring `python_renderer.py`'s own pure-function
style. Proceeds through Build/Test/Commit per the Autonomy Default.

## Requirement

Part of `13.data-architecture-layer.md`. R45 (SQL derives from the same canonical model,
never independently authored), spec section 17-18.

## Scope decisions

1. **PostgreSQL only**, per the PRD's own Non-Goals addition — no dialect parameter.
2. **Tables are emitted in FK-dependency order** (a referenced entity's `CREATE TABLE`
   always precedes any table with a `FOREIGN KEY` into it) — a topological sort over
   `references_entity`, mirroring `python_renderer.py::_topological_order`'s own shape but
   keyed on the FK graph instead of `requires`.
3. **The referenced column is looked up from the real target entity's own primary-key
   attribute name**, never hardcoded to `id` — defensive fallback to `id` only if a
   malformed entity genuinely has no primary key marked (shouldn't happen for a
   Stage-6-derived entity, but never crashes on it).

## Build (`backend/data_architecture/engine.py`)

`render_sql_ddl(entities: List[DataEntity]) -> str` + `_topological_order_by_fk` (private
helper). One `CREATE TABLE` statement per entity, columns then `FOREIGN KEY` clauses,
separated by a blank line between statements.

## Test (`tests/test_data_architecture.py`)

1. Two entities with a real FK (`documents` -> `document_chunks`): the referenced table's
   `CREATE TABLE` appears first in the output; the FK clause references the real target
   table and its real (non-`id`-hardcoded) primary key column name.
2. `PRIMARY KEY`/`NOT NULL` markers appear exactly where the model says they should; a
   nullable, non-PK, non-FK column gets neither marker.
