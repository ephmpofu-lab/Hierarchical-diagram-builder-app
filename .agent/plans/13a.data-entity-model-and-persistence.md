# Plan 13a: Data Entity Model + Persistence

**Complexity: Simple.** Pure models + a persistence module mirroring an already-established
convention (`backend/component/repository.py`). Proceeds through Build/Test/Commit per the
Autonomy Default.

## Requirement

Part of `13.data-architecture-layer.md`. R43 (stable Data IDs), R44 (compound-key
anchors), R45 (one canonical model).

## Scope decisions

1. **`DataAttribute`/`DataRelationship`/`DataEntity`/`DataAnchor`/`DataArchitecture`** —
   five new models, no behavior yet (that's 13b-13d). `DataAnchor` is the compound key
   itself made real: `domain` (Workflow ID) + `node_id` (real Atomic step id) + `data_id` +
   `operation` — never a bare id alone (R44).
2. **A step with no persistence need simply produces zero `DataAnchor` rows** — `TRANSIENT`
   is not a stored operation value, it's the absence of an anchor. Keeps the model honest:
   only real persistence relationships are ever represented.
3. **`node_label` is denormalized onto `DataAnchor`** (the Atomic step's own label at
   authoring time) so a UI can render "WF01:N08 — Split Text Into Chunks — WRITE" without
   a second tree lookup — a real, already-known fact captured once, not invented.
4. **Persistence mirrors `backend/component/repository.py` byte-for-byte**
   (`data_architectures/{domain}.json`), not a shared/reused module — same reasoning 11l
   gave for keeping the Component Tree's own repository separate from the Workflow Tree's.

## Build

1. **`backend/models.py`** — `DataAttribute` (`name`, `type`, `is_primary_key`,
   `is_foreign_key`, `references_entity: Optional[str]`, `nullable`, `default`);
   `DataRelationship` (`from_entity`, `to_entity`, `cardinality`); `DataEntity` (`id`,
   `name`, `description`, `database`, `attributes`, `domain`); `DataAnchor` (`domain`,
   `node_id`, `node_label`, `data_id`, `operation`); `DataArchitecture` (`domain`,
   `version`, `entities`, `relationships`, `anchors`).
2. **`backend/data_architecture/__init__.py`** (new package) +
   **`backend/data_architecture/repository.py`** — `load_data_architecture(domain)`,
   `save_data_architecture(tree)`.

## Test (`tests/test_data_architecture.py`, new file)

1. Round-trip: build a small `DataArchitecture` (2 entities, 1 relationship, 2 anchors),
   save then load, confirm every field survives identically.
2. `load_data_architecture` returns `None` for an unknown domain, never raises.
