# Plan 12a: `docs/` Folder + Planning-Artifact Diagram Engine (unblocked slice)

**Complexity: Medium.** Frontend-only (no backend/schema changes — confirmed below), but
introduces a genuinely new visual pattern (hub-and-spoke) not used anywhere else in the app.
Proceeds through Build/Test/Commit per the Autonomy Default; not Complex enough to warrant a
DP9 pause.

## Requirement

Part of Module 12 (R38-R40). Per the resolved scope: `docs/` holds the *current domain's*
own planning artifacts, not ARCHITEQ's self-documentation — sitting in the same Level 1
folder view 10c already built, next to `architeq_{domain}/`.

## What's actually unblocked today (per the corrected OQ6)

Of the six DP11 artifacts, only the Engineering-Plan-equivalent has real per-domain content
right now (Modules 5-8, already rendered by 10c's folder/file/function browser). The other
five — PRD, TDD, App Flow, Design Brief, Backend Schema — have no per-domain generator yet
(PRD-equivalent depends on Module 11's Stage -3, not built; the other four have no generator
scoped at all). This sub-plan builds:
1. The `docs/` folder entry appearing in Level 1, alongside `architeq_{domain}/`.
2. Five of the six artifacts (PRD, TDD, App Flow, Design Brief, Backend Schema) rendering
   R40's honest "not generated yet" state, each naming its own specific blocking reason —
   not the same generic message repeated five times, since the reasons genuinely differ
   (Module 11 not built vs. no generator scoped at all).
3. The Engineering-Plan-equivalent's hub-and-spoke view: hub = domain name + one-line
   description; spokes = one per Layer in the frozen tree (real data, already in
   `state.tree`), up to 6 — clicking a spoke jumps into 10c's existing folder browser
   scoped to that Layer's files. This is not a second renderer for the same data; it's a
   summary view over data 10c already fully renders, per UI1 (don't invent a second screen
   for something an existing one already covers).

## Explicitly deferred (real open question, not guessed at here)

Whether TDD/App-Flow/Design-Brief/Backend-Schema-equivalents ever get real per-domain

## Build (`static/js/decompose.js`, `static/css/style.css`)

1. **`renderPyLevel1` extended** — a `docs/` folder row added above (or alongside)
   `architeq_{domain}/`, with 6 file rows (PRD.md, TDD.md, AppFlow.md, DesignBrief.md,
   BackendSchema.md, EngineeringPlan.md), each showing "not generated yet" inline except
   EngineeringPlan.md.
2. **`docArtifactStatus(artifactId)`** — pure function returning
   `{status: "built"|"missing", blockedReason: string}` per artifact. Hardcoded per current
   real state (not computed from anything dynamic yet, since only one generator exists):
   `engineering_plan` -> built; `prd` -> missing, reason "depends on Module 11's Stage -3
   (Requirements Engineering), not yet built"; `tdd`/`app_flow`/`design_brief`/
   `backend_schema` -> missing, reason "no generator scoped for this artifact yet (see
   ARCHITEQ-PRD.md OQ6)".
3. **`openDocArtifact(id)`** — Level 3 renders either the honest-unavailable state
   (`docArtifactStatus` -> missing) or, for `engineering_plan`, the hub-and-spoke view.
4. **`renderHubAndSpoke(hub, spokes, onSpokeClick)`** — new, generic (not
   Engineering-Plan-specific) so a future artifact with real content can reuse it without a
   rewrite. Renders one hub card + up to 6 spoke cards positioned 3-left/3-right, connector
   lines drawn via `getBoundingClientRect()` after layout (same technique the reference
   mockup uses) — recomputed on window resize. If more than 6 spokes are ever passed, throws
   rather than silently truncating or reflowing into an unsupported layout (per the
   already-flagged known limitation in `10.ui-shell-rebuild.md`).
5. **CSS** — new `.decompose-hub`, `.decompose-spoke`, `.decompose-doc-conn` etc. classes,
   built from the same tokens 10c already uses (`var(--surface)`, `var(--border)`,
   `var(--accent)`, `var(--text)`, `var(--text-muted)`) and the same monospace stack for the
   filename subtitle — no new color system, no JetBrains Mono, per the standing theme
   decision. Hub visually heavier (larger padding, shadow via `--shadow`) than spokes; all
   spokes equal weight to each other regardless of content length (UI5/UI9).
6. **UI10 compliance** — the "not generated yet" state uses the warning color token plus an
   explicit "not generated yet" text label and icon, never amber alone.
