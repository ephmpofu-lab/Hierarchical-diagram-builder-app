# Plan 13g: Workflow-Active Data Anchors + Faint Underlay

**Complexity: Simple.** Additive to `renderN8nDiagram` (already rebuilt in 10a-iii);
compact anchors + a small faint reference panel, never a full ERD rendered behind the node
tiles (avoids exactly the "must not interfere with workflow readability" risk the spec
itself warns against). Proceeds through Build/Test/Commit per the Autonomy Default.

## Requirement

Part of `13.data-architecture-layer.md`. R47 (Workflow-active/Data-underlay prominence),
R48 (compact Data Anchors on data-touching nodes), spec section 8.

## Scope decisions

1. **Compact anchors, not a full entity render, on each node tile** — one small text line
   per real `DataAnchor` matching that node's `step_id` (compound key: same domain + real
   `node_id`), showing `{data_id} {operation}` (e.g. "D02 WRITE"), stacked if a node has
   more than one. A node with none renders nothing extra (matches R48's own "relevant
   workflow nodes" wording, never every node).
2. **The faint underlay is a real, labeled reference panel, not a rendered-behind-the-
   nodes ERD.** Rendering actual entity boxes behind node tiles at low opacity risks the
   exact "must NOT interfere with workflow readability" failure section 8 warns against;
   a small, low-opacity side panel listing the real entity ids/names (never decorative
   placeholder data) satisfies "a referenced architectural layer" honestly without that
   risk. `renderFaintUnderlay(title, items)` is written generically so 13h's reverse case
   (faint real workflow reference while Data is active) reuses it, not a second
   implementation.
3. **Anchors/underlay only render when `state.dataArchitecture` is already loaded** — if
   the user hasn't switched to the Data layer yet this session, `state.dataArchitecture`
   is still `null`; no anchors/underlay show until it's fetched (same lazy-fetch posture
   13f's `selectDataLayer` already established). This is a real, honest state, not a bug —
   flagged here so 13h doesn't have to re-decide it.

## Build (`static/js/decompose.js`, `static/css/style.css`)

1. `renderFaintUnderlay(title, items)` — a small, low-opacity (~15%) labeled panel, real
   content only.
2. `renderN8nDiagram`: when `state.workflowDataLayer === "workflow"` and
   `state.dataArchitecture` is loaded, each node's group gains one `<text>` per matching
   anchor (`{data_id} {operation}`); the diagram wrap gains a `renderFaintUnderlay("Data
   Layer (reference)", entityLabels)` panel.
3. CSS: `.decompose-n8n-anchor-text`, `.decompose-faint-underlay` (opacity ~0.15).

## Test

Standalone Playwright harness: a fixture with 2 anchors on 2 different real node step ids
confirms exactly those 2 nodes show anchor text (`"D02 WRITE"` etc.), a third node with no
anchor shows none; the faint underlay panel lists the real entity ids/names at reduced
opacity. Zero JS errors.
