# Plan 11e: Tree Reconciliation (CD6)

**Complexity: Medium.** Pure validation logic (no AI call), but a genuinely nuanced check —
flagging one real, honestly-stated limitation rather than solving it with guesswork.
Proceeds through Build/Test/Commit per the Autonomy Default.

## Requirement

R29 (`ARCHITEQ-PRD.md`): "Before either tree is considered frozen, every Component Tree
attribute resolves to exactly one Workflow Tree variable and vice versa; a tree with an
attribute or variable that has no counterpart in the other is rejected (CD6, the
Reconciliation Rule)."

## Known limitation, stated up front rather than guessed around

CD6's predicate says an attribute and a variable "share its canonical name." This sub-plan
implements "canonical name" as a normalized name comparison (lowercase, non-alphanumeric
characters stripped — so `"Batch Size"` and `"batch_size"` reconcile, since both normalize
to `"batchsize"`). This is a real, deterministic, mechanical check — but it only reconciles
names that are, underneath formatting differences, the *same words*. It does not perform
semantic matching between genuinely different-looking names for the same fact (the
Dual-Tree-Architecture doc's own worked example, `"Model"` vs `"model_name"`, would NOT
reconcile under this check). Solving that would need either an explicit shared-alias
mechanism at authoring time (Stage 0 and Stage 4 deliberately naming things identically) or
a genuine AI judgment call — out of scope here, flagged as a real gap for a later sub-plan
or for Stage 0/Stage 4's own prompts to converge on shared naming conventions, not silently
papered over with fuzzy matching now.

## Build (`backend/component/engine.py`)

1. **`_canonical_name(name)`** — lowercase, strip everything but letters/digits.
2. **`check_tree_reconciliation(attributes, tree) -> List[str]`** — takes the full list of
   Component Tree `Attribute` objects for a domain and the domain's real `DomainTaskTree`
   (Workflow Tree). Flattens every `Variable.name` across every Atomic step node in `tree`,
   canonicalizes both sides, and returns one violation message per attribute with no
   canonical match among the variables, plus one per variable with no canonical match among
   the attributes. Empty list means fully reconciled.

## Test (`tests/test_engineering_decomposition.py`)

1. A hand-built `Attribute` list and `DomainTaskTree` where every attribute name
   canonically matches exactly one variable name (allowing for case/spacing/underscore
   differences) — confirm zero violations.
2. One attribute with no matching variable — confirm exactly one violation naming that
   attribute.
3. One variable with no matching attribute — confirm exactly one violation naming that
   variable (checked independently of test 2, i.e. the function checks both directions,
   not just attribute-to-variable).
4. Confirm case/formatting differences alone (`"Batch Size"` vs `"batch_size"`) do NOT
   produce a violation — this is the one thing the mechanical check is actually meant to
   handle.
