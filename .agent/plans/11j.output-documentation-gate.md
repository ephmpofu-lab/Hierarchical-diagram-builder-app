# Plan 11j: Output Documentation Gate (R32-R33, CD10)

**Complexity: Medium.** Two independent predicate checks (rationale-on-genuine-choice;
UI-conditional App-Flow/Design-Brief) added as new Validator-style functions, following the
same "check function over flat data, no orchestrator yet" shape as 11d/11e/11i. Proceeds
through Build/Test/Commit per the Autonomy Default.

## Requirements

- R32: "Every Component whose realization required a genuine implementation choice (not a
  deterministic single match) carries a one-line rationale for that choice; a Component
  Tree with an unrationalized genuine choice is rejected at freeze time (CD10,
  Tech-Decisions-equivalent). The same applies to a Workflow Tree Atomic step whose
  node-mapping was a genuine, non-deterministic choice."
- R33: "If a Component Tree contains at least one UI-tagged component, it carries an
  App-Flow-equivalent and a Design-Brief-equivalent before freezing; if it contains none,
  both are explicitly recorded as 'not applicable,' never silently absent (CD10)."

## Scope decisions

1. **`requires_rationale`/`rationale` are data fields, not AI-computed here.** Whether a
   given Component's realization (or a given Atomic step's node-mapping) was a "genuine,
   non-deterministic choice" is a judgment made at authoring time (Stage -1/Stage 3's own AI
   call, or a human editing later) — out of scope for this sub-plan to decide *when* that
   flag gets set (no orchestrator exists yet, same standing deferral as 11a-11i). This
   sub-plan adds the fields and the check functions that enforce the predicate given
   whatever values are present, exactly the same posture 11e's reconciliation check and
   11d/11h's attribute-leaf check already established.
2. **`is_ui_tagged` is a plain bool on `Component`**, not a new tagging subsystem — mirrors
   how `pillar_tags`/`classification` already exist as simple fields elsewhere in this
   codebase rather than a generic tag registry. Only Components (Python track) can be
   UI-tagged; R33 does not apply to the Workflow Tree/n8n track at all (CD10's own text:
   "n8n output is headless by construction").
3. **`ComponentTreeDocumentation` is one small new model**, not folded into `Component` —
   the App-Flow/Design-Brief-equivalent is a property of the whole Component Tree (one
   system being described), not of any single Component, matching how the real
   `ARCHITEQ-APP-FLOW.md`/`ARCHITEQ-DESIGN-BRIEF.md` are each one document per project, not
   one per module.
4. **Two separate rationale-gate functions, not one**, same reasoning as 11i's two rollup
   functions: `check_component_rationale_gate` walks a flat `List[Component]` (Python
   track); `check_workflow_tree_rationale_gate` walks a `DomainTaskTree`'s Atomic step nodes
   (Workflow Tree track) — genuinely different shapes, per CD10's own text splitting the
   Tech-Decisions-equivalent into a Component Tree freeze-step check and a Workflow Tree
   approve-step check.
5. **`check_ui_documentation_gate` implements R33's full conditional, including the
   "both-or-neither" edge case** named in CD10's own predicate ("a tree with a UI-tagged
   component but no App-Flow/Design-Brief content, and no 'not applicable' is possible, is
   rejected") — i.e. `not_applicable=True` together with a UI-tagged component present is
   itself a violation, not silently accepted.

## Build (`backend/models.py`, `backend/component/engine.py`)

1. **`Component` gains**: `requires_rationale: bool = False`, `rationale: Optional[str] =
   None`, `is_ui_tagged: bool = False`.
2. **`TaskTreeNode` gains**: `requires_rationale: bool = False`, `rationale: Optional[str] =
   None` (Atomic step level only, same comment convention as `pillar_tags`/`variables`).
3. **New model `ComponentTreeDocumentation`**: `app_flow_equivalent: Optional[str] = None`,
   `design_brief_equivalent: Optional[str] = None`, `not_applicable: bool = False`.
4. **`check_component_rationale_gate(components: List[Component]) -> List[str]`** — one
   violation per component where `requires_rationale` is True and `rationale` is empty/None.
5. **`check_workflow_tree_rationale_gate(tree: DomainTaskTree) -> List[str]`** — same check,
   over Atomic step nodes only.
6. **`check_ui_documentation_gate(components: List[Component], documentation:
   Optional[ComponentTreeDocumentation]) -> List[str]`** — if any component has
   `is_ui_tagged=True`: violation if `documentation` is None, if `not_applicable=True`, or
   if either `app_flow_equivalent`/`design_brief_equivalent` is empty. If no component is
   UI-tagged: violation if `documentation` is None or `not_applicable` is not True.

## Test (`tests/test_engineering_decomposition.py`)

1. `check_component_rationale_gate`: a component with `requires_rationale=True` and a
   non-empty rationale passes (no violation); `requires_rationale=True` with empty/None
   rationale violates; `requires_rationale=False` never violates regardless of rationale.
2. `check_workflow_tree_rationale_gate`: same 3 cases on a hand-built `DomainTaskTree` with
   one Atomic step node.
3. `check_ui_documentation_gate`: no UI-tagged component + `not_applicable=True` passes; no
   UI-tagged component + `not_applicable=False` (or `documentation=None`) violates; one
   UI-tagged component + both fields present passes; one UI-tagged component + only one
   field present violates; one UI-tagged component + `not_applicable=True` violates (the
   both-or-neither edge case).
