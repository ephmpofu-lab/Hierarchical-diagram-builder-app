Part of `10.ui-shell-rebuild.md`: "reconciling the mockup's Empty/History/Canvas screens

## What's actually missing, traced directly

`renderHomeView` already satisfies AMENDMENT 4's core requirement (the intent input never
disappears once history exists) and already lists known domains. Two real gaps against the
mockup's Empty/History screens:
1. **No example chips** on the empty/input area (the mockup's 3 example chips that fill the
   intent textarea).
2. **History entries are a bare domain-name list**, not the mockup's richer card (title +
   a meta line). `GET /api/decompose/domains` today returns `List[str]` (`taxonomy_repo.
   list_domains()` just globs filenames) — no timestamp, no size, nothing else real to show.

## Scope decisions

1. **Example chips are static, real example texts** (the mockup's own 3: "I want to develop
   a RAG", "I want to automate invoice processing", "I want to build a support ticket
   triage system") — clicking one fills the textarea, it does **not** auto-submit or jump
   straight to a screen the way the mockup's own demo-shortcut wiring does (that was a
   presentation shortcut for the mockup's click-through demo, not real product behavior).
2. **History cards show only real, already-on-disk data — no fabricated mode/validation
   badges.** The mockup's history cards show a "mode" (Python/n8n) and a "validated / N
   open issues" badge — neither has a real backing fact in this app: this app never
   persists "which mode was last rendered" per domain (render caches are session-only), and
   a domain only ever appears in this list once its tree is *frozen*, which by construction
   already passed the Validator (R9) — there is no real "N open issues" state a frozen
   domain could be in. Rather than invent either, the real facts actually available from
   the tree file already on disk are used instead: a "last touched" date (the tree file's
   own mtime) and a real atomic-step count (from the tree's own contents) — both genuinely
   informative, both zero fabrication.
3. **`GET /api/decompose/domains`'s response shape changes** from `List[str]` to
   `List[DomainSummary]` (`domain`, `last_touched`, `atomic_step_count`) — a deliberate,
   real breaking change (one existing test updated to match, not shimmed).
4. **Reuses the Launchpad's own `.launchpad-recent-row`/`.launchpad-recent-meta` CSS
   convention** for the upgraded history cards, rather than inventing new card styling this
   codebase doesn't already have a precedent for.

## Build

1. **`backend/models.py`** — new `DomainSummary(domain: str, last_touched: str,
   atomic_step_count: int)`.
2. **`backend/taxonomy/repository.py`** — `list_domain_summaries() -> List[DomainSummary]`,
   reading each tree file's real mtime (`path.stat().st_mtime`, ISO-formatted) and counting
   real Atomic step nodes from the already-loaded tree.
3. **`backend/api.py`** — `GET /decompose/domains` response_model becomes
   `List[DomainSummary]`, body calls `list_domain_summaries()`.
4. **`static/js/decompose.js`**:
   - `renderHomeView`: 3 example chips below the intake input/button, each filling
     `input.value` on click (no auto-submit).
   - History list upgraded to a card per domain (title = domain name, meta = `formatDate`d
     `last_touched` + real atomic-step count), reusing `.launchpad-recent-row`/`.launchpad-
     recent-meta`; `formatDate` ported from `library.js`'s own existing helper (same
     locale-date format, not a new convention).
   - `loadKnownDomains` updated for the new response shape.

## Test

1. **Backend** — `test_domains_endpoint_lists_known_domains` updated to check the new
   shape (`any(d["domain"] == "rag" for d in response.json())`); new
   `test_list_domain_summaries_reports_real_atomic_step_count` confirms the count matches
   the real frozen `rag` tree's actual Atomic step nodes.
2. **Frontend** — standalone Playwright harness: clicking an example chip fills the
   textarea with the exact example text and does not change `state.view`; a fixture
   `knownDomains` list with 2 entries renders 2 history cards showing the real domain name,
   a formatted date, and the real atomic-step count. Zero JS errors.
