# Plan 13h: Data-Active Mode + Faint Workflow Underlay

**Complexity: Simple.** The reverse of 13g, reusing `renderFaintUnderlay` (already built
generic). Proceeds through Build/Test/Commit per the Autonomy Default.

## Requirement

Part of `13.data-architecture-layer.md`. R47 (Data-active/Workflow-underlay prominence),
spec section 11 (the faint reference must be the REAL workflow: domain/Workflow ID + real
node ids + real node names, never a decorative placeholder).

## Scope decisions

1. **The faint Workflow reference is built from `state.tree`** (already loaded for the
   canvas) — one line per real Layer, its real Atomic step labels joined left to right
   (`"Ingestion: Read File → Split Into Chunks → ..."`), matching the spec's own
   `[N01] → [N02] → [N03]` worked example concretely, using each step's real label rather
   than a bare node id (more legible, still fully real).
2. **Reuses `renderFaintUnderlay` from 13g verbatim** — no second implementation.

## Build (`static/js/decompose.js`)

`_buildWorkflowUnderlayItems(tree)` — walks `root_ids` -> Layer -> Sub-task -> Atomic step,
one string per Layer. `renderOutputSection`'s Data-active branch gains
`renderFaintUnderlay("Workflow Layer (reference): {domain}", items)`, appended after the
ERD diagram.

## Test

Standalone Playwright harness: a 2-Layer fixture tree confirms the underlay shows exactly 2
rows, each naming its real Layer and real Atomic step labels in the correct left-to-right
order. Zero JS errors.
