# Plan 10b-i: Dual Labels + Needs-Config Badge (CR11)

**Complexity: Simple.** Frontend-only, purely additive to `renderN8nDiagram` (just rebuilt
in 10a-iii) using data already present on the fetched `N8nWorkflow` — no backend change.
Proceeds through Build/Test/Commit per the Autonomy Default.

## Requirement

Part of `10b.n8n-node-tile.md`. CR11: "every rendered node shows two distinct labels: a
display name and a real node type string." Plus a "needs-config state" visual indicator
named in `10.ui-shell-rebuild.md`'s own sub-plan description.

## Scope decisions

1. **The real type string is already on `N8nNode.type`** — no new data needed, just a
   second `<text>` element, visually distinct (smaller, muted, monospace) from the display
   name per CR11's "displayed together, not merged."
2. **"Needs configuration" is a real, mechanically-checkable predicate over already-fetched
   data, not a new AI judgment or backend field**: a node needs configuration if any value
   in its own `parameters` dict is a literal empty string (`""`) — i.e. `_build_parameters`
   (`node_mapper.py`) never overlaid a real declared `Variable.default` onto that schema
   parameter, so it's still sitting at the schema's own empty placeholder. Computed
   client-side from `node.parameters`, already present on every fetched `N8nNode`.
   Nested/non-string parameter values (e.g. Set's `assignments`, If's `conditions`) are
   deliberately not flagged by this check — they're structural, not "needs a value" in the
   same sense a flat string default is.
3. **Box height grows from 50 to 58px** to fit two text lines without crowding — a small,
   local constant change; ports/badge positions all derive from `boxHeight` already, so
   nothing else needs updating by hand.

## Build (`static/js/decompose.js`, `static/css/style.css`)

1. `renderN8nDiagram`: `boxHeight` 50 -> 58; a `needsConfiguration(node)` helper; a second
   `<text>` per node showing `node.type`; a small badge `<circle>` (top-right corner of the
   box) drawn only when `needsConfiguration(node)` is true.
2. `style.css`: `.decompose-n8n-node-type-text` (muted, monospace, smaller than the display
   name); `.decompose-n8n-needs-config-badge` (reuses the existing `--warning` token).

## Test

Standalone Playwright harness (same pattern as 10a): a fixture with one node whose
`parameters` includes an empty-string value and one whose parameters are all non-empty;
confirm the type-label text renders for both, and the needs-config badge renders only for
the first. Zero JS console errors.
