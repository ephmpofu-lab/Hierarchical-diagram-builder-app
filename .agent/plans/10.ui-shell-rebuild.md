# Plan 10: UI Shell Rebuild (Module 10, per `reference/architeq-ux-mockup.html`)

**Complexity: Complex.** Full rebuild of the Canvas state's rendering (current
`renderTreeDiagram`/`renderN8nDiagram` in `decompose.js` predate the entire CR1-18 corpus
and implement none of stage-zone layout, rounded-orthogonal routing, drag/pan/zoom, or the
dual Python-folder-browser/n8n-canvas split). Broken into sub-plans below per DP5/DP9; this
file is the index only.

## Blockers — resolved

1. **CR3 vs CR15**: resolved. `n8n-canvas-rules.md` CR3 amended in place (Statement/
   Predicate/new "Superseded in part by CR15" note) — same treatment NT10 got from
   CR11/CR12. Left-to-right sequencing still holds; the row/stage-independence clause is
   withdrawn.
2. **CR16 vs the mockup's branch routing**: resolved by fixing the mockup, not the rule.
   `reference/architeq-ux-mockup.html`'s `branchPath` (top-entry) removed; branch edges now
   call `crossPath` with a short local lane, same left-port entry as every other connection
   class. No exception added to CR16.
3. **Missing node types**: resolved. `rules/n8n_node_schemas.json` expanded with 5 new
   verified entries (Stop And Error, Extract From File, Read/Write Files from Disk, Google
   Drive, Notion), each checked against docs.n8n.io. A 6th (Embeddings OpenAI, for
   `embed_chunks`) was verified but deliberately kept OUT of the actively-matched `nodes`
   array in a new `deferred_cluster_nodes` section — it's a LangChain cluster sub-node
   requiring a parent Vector Store node the current Node Mapper can't represent yet; adding
   it to `nodes` would have made `match_schema()` emit an orphaned, non-importable node,
   the exact defect NT2/R14 exist to prevent. Confirmed no test depends on the old 6-entry
   shape (470 passed, 3 schema-specific tests green).
4. **Build-status sequence**: resolved, applies at 10d build time (not yet built) — Workflow
   Tree stages only; the Module-11-only lines get dropped from the real implementation, not
   from the reference mockup (which stays as a demonstration of eventual full-pipeline
   behavior once Module 11 exists).
5. **Theme**: resolved, applies at reskin time (any sub-plan touching CSS) —
   `ARCHITEQ-DESIGN-BRIEF.md`'s tokens win. The mockup's interaction/structural logic
   (drag, zoom, pan, stage-zone layout, rounded-orthogonal routing with left-port entry
   everywhere, the Python folder/file/side-panel split, progressive build reveal,
   idle-retract) is reproduced exactly; only colors/fonts get reskinned to the shipped
   palette.

## Sub-plans

1. **10a.canvas-foundation.md** — Node Mapper layout (stage-zone allocation per CR15,
   9-10/row wrap per CR4) + SVG Renderer routing (rounded-orthogonal per CR5, port-entry
   per CR16, connection classification per CR18, including the corrected branch routing) +
   pan (middle-mouse drag) + zoom (scroll-wheel, cursor-centered). Backend:
   `backend/render/node_mapper.py` gains real stage-zone computation, replacing whatever
   ordering it uses today. Frontend: `decompose.js` SVG edge/port drawing rewritten to
   match. Unblocked now; not yet started.
2. **10b.n8n-node-tile.md** — Node tile (icon, dual display-name + real-type labels per
   CR11, ports, needs-config state), tooltip, detail panel wiring, suggestion/configuration
   mechanism (chip selection → confirm → collapse, per-parameter user-input fields with
   live validation), now covering the 5 newly-verified node types. Depends on 10a for tile
   positioning. Unblocked now; not yet started.
3. **10c.python-file-browser.md** — Folder → File → Function three-level view + side panel
   (growing file, always-complete). Backend: `python_renderer.py` needs a new
   folder/file-grouping capability it doesn't have today. Frontend: the Level 1/2/3 browser
   + side panel from the mockup. Self-contained, real backend data (R12) already exists as
   a base to extend. **Starting here** (see `10c.python-file-browser.md`).
4. **10d.progressive-build-animation.md** — the build-status line sequence (Workflow Tree
   stages only, per the resolved blocker 4) + streamed reveal of Layer/Sub-task/Atomic-step
   nodes + auto-fix-on-failure sequence. **Built, tested, committed** — real, computed-
   from-the-actual-tree status lines (not fabricated live progress: `propose_tree`'s retry
   loop runs entirely inside the single synchronous `/draft` call, traced directly before
   building this); `reviewing_draft` upgraded from a plain-outline placeholder to the real
   Tree Diagram with a streamed Layer/Sub-task/Atomic-step reveal. The "auto-fix-on-failure"
   sequence is deliberately NOT a live animation (no real per-attempt signal exists) —
   failure honestly surfaces the real violation count and flows into the existing
   `reviewing_draft` human-review screen; a true live per-attempt progress feed would need
   new Cycle-style async backend infrastructure, named here as a real, separate future
   enhancement.
5. **10e.refine-bar-and-idle-retract.md** — persistent refine bar (collapse/expand,
   idle-retract), detail panel idle-retract. Small, self-contained. **Built, tested,
   committed** — ported the mockup's own `expandRefineBar`/`collapseRefineBar`/
   `armRefineIdleRetract`/`armPanelIdleRetract` timing (6s/7s) onto real state and real DOM
   elements; refine bar's existing inline-flow position left untouched (re-positioning to a
   floating pill was never asked for here).
6. **10f.screen-state-wiring.md** — reconciling the mockup's Empty/History/Canvas screens
   against `decompose.js`'s existing `home`/`drafting`/`reviewing_draft`/`canvas` states
   (largely already built in AMENDMENT 4/5; this sub-plan is the delta, not a rebuild).
   **Built, tested, committed** — the two real gaps were example chips (added, real static
   prompts, no auto-submit) and history-card metadata (`GET /decompose/domains` now returns
   real per-domain `last_touched`/`atomic_step_count`, not the mockup's fabricated "mode"/
   "validated vs N issues" badges, which have no real backing fact in this app -- a frozen
   tree already passed the Validator by construction, and render mode is never persisted
   per domain).
7. **10g.real-export.md** — Export produces real files (a downloadable zip/tree of the
   Python module structure) or real `workflow.json` (already exists per R14/`n8n_exporter.py`).
   Depends on 10c and existing n8n export. **Built, tested, committed** — new
   `backend/render/python_exporter.py` mirrors `n8n_exporter.py`'s own "renderer computes
   content, exporter packages the real artifact" split, using Python's stdlib `zipfile`
   (no external JS zip dependency, matching this app's zero-external-JS-dependency
   posture); folder/file grouping mirrors `decompose.js::groupPythonRenderByFile` exactly,
   now computed server-side.
8. **10h.reskin-to-design-brief.md** — apply `ARCHITEQ-DESIGN-BRIEF.md`'s shipped palette/
   type tokens across whichever of 10a-10g introduced mockup-colored markup, per the
   resolved theme decision. Runs after the sub-plans it reskins, not before. **Audited,
   resolved, committed** — turned out to be an audit, not a build: every 10a-10g CSS rule
   was already written directly against the shipped Design Brief tokens, confirmed by
   direct grep (zero matches for the mockup's own literal colors/fonts anywhere in
   `style.css`). Nothing to reskin. **Module 10's UI Shell Rebuild (10a through 10h) is now
   fully complete.**

## Note: the mockup's own visual theme differs from `ARCHITEQ-DESIGN-BRIEF.md` — RESOLVED (10h)

The mockup uses its own token set (`--bg:#0B0C0F`, `--accent:#7C8CFF`, JetBrains Mono for
code) which does not match the already-documented, already-shipped tokens in
`ARCHITEQ-DESIGN-BRIEF.md` (`--bg:#161616`, `--accent:#2563eb`, no JetBrains Mono). Per DP11/
CD10, `ARCHITEQ-DESIGN-BRIEF.md` is the source of truth. Resolved in practice, not just in
theory: every sub-plan (10a-10g) was built directly against the shipped Design Brief tokens
from the start (`var(--accent)`, `var(--surface)`, `var(--warning)`, etc.) — only the
mockup's *interaction/structural logic* (stage-zone layout, rounded-orthogonal routing,
pan/zoom, collapse/expand timing, progressive reveal) was ported, never its literal colors
or fonts. 10h audited this directly (grepped for the mockup's own literal values across
`style.css` — zero matches) and confirms there is nothing left to reskin.
