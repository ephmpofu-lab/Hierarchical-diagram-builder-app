# Plan 12: Planning Artifact Diagram Engine (Module 12)

**Complexity: Complex.** Renders the *current domain's own* six DP11 planning artifacts
(never ARCHITEQ's own self-documentation) as a `docs/` folder next to that domain's
`architeq_{domain}/` code folder, hub-and-spoke diagram by default per UI12, text view one
interaction away. Per `ARCHITEQ-PRD.md` R38-R40. Broken into sub-plans per DP5/DP9 --
this file is the index only, mirroring Module 11's and Module 13's own precedent.

## Grounding decisions (resolved before any sub-plan starts)

1. **Six deterministic generators, not five honest gaps forever.** OQ6 originally left
   TDD/App-Flow/Design-Brief/Backend-Schema-equivalents with no generator scoped at all.
   12b resolves this: every one of the six artifacts (PRD, TDD, App Flow, Design Brief,
   Backend Schema, Engineering Plan) is now a pure, deterministic function of a domain's
   already-frozen Workflow Tree, and (where relevant) its Component Tree and Data
   Architecture -- never an LLM call, never ARCHITEQ's own repository documents used as
   end-user content.
2. **A source tree's absence is still honest, per R40.** App Flow and Design Brief require
   a frozen Component Tree to exist (so whether the domain has a UI-tagged component is
   even knowable); Backend Schema requires a frozen Data Architecture. Absent either, the
   artifact renders R40's "not generated yet" state naming that specific dependency --
   never fabricated content, never a generic message reused across artifacts with
   genuinely different blockers.
3. **The supplied mockup (`reference/architeq-ux-mockup.html`) is authoritative** for the
   diagram surface: one central hub (icon, title, filename, description), up to six fixed
   satellite positions (three per side), dashed connector curves measured from real card
   `getBoundingClientRect()` positions, diagram-first with a one-interaction Full text
   toggle. Existing ARCHITEQ theme tokens only -- `var(--font-mono)` (headed by JetBrains
   Mono, already the app's standing named stack) for code/path text, no new color system.

## Sub-plans

1. **12a.docs-folder-and-diagram-engine.md** -- the unblocked slice: `docs/` folder entry
   in the existing Level 1 Python browser, the generic `renderHubAndSpoke` diagram
   primitive (six fixed positions, measured dashed connectors), and the
   Engineering-Plan-equivalent's real hub-and-spoke view (the only artifact with a real
   generator at that point). The other five artifacts rendered R40's honest
   "not generated yet" state. **Built, tested, committed.**
2. **12b.real-planning-artifact-generation.md** -- completes R38-R40: a deterministic
   `backend/planning_artifacts.py` generator for all six artifacts, a new
   `GET /decompose/domains/{domain}/planning-artifacts` endpoint, and frontend rendering
   that replaces the hardcoded status map with the real API-backed data (real hub icon,
   title, filename, and description per artifact -- not a single hardcoded "Engineering
   Plan" hub reused for every one), while preserving 12a's own per-Layer navigation for the
   Engineering Plan specifically. **Built, tested, committed** -- Module 12 (R38-R40) is
   now fully complete.

## Explicitly resolved, no longer open

OQ6 (per `ARCHITEQ-PRD.md`'s Open Questions) is resolved by 12b: all six artifacts have a
real per-domain generator today. What remains genuinely per-domain-conditional (not a gap
in ARCHITEQ itself) is whether a *given* domain's own Component Tree / Data Architecture
exist yet -- that conditionality is R40's own honest-unavailable-state design, not an open
question about ARCHITEQ's scope.
